# Architecture explainer

Identify the audience and the relationships or execution flow that prose cannot
show clearly. Base the explainer on the current code and authoritative design,
not inferred components.

Use the smallest useful visual: a flow for execution, a tree for ownership, or a
table for exact mappings. An HTML explainer should be self-contained when
practical, accessible, readable without animation, and accompanied by concise
text that defines scope and terminology.

After implementation, verify names, links, and flows against the final code.
Store the artifact only when the repository has an agreed documentation location
and the user has authorized the change.
