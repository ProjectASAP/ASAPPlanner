# Exploration and proof of concept

Write the question, hypothesis, success signal, time or scope boundary, and
expected artifact before experimenting. Prefer the cheapest experiment that can
discriminate between alternatives.

Keep shortcuts and unsupported assumptions visible. Do not present POC code as
production-ready or introduce it into production paths without explicit
authorization and normal design, testing, security, and maintenance review.

Conclude with evidence, limitations, rejected hypotheses, and a recommendation:
adopt, investigate further, or stop. Separate reusable findings from disposable
experimental code.
