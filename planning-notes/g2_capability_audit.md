# G2 (#676) capability audit: what does deleting the legacy search lose?

Read-only. Compared `origin/main` (e80cfef1) with `origin/stack/g2-legacy-removal` (b5e08bbe), plus the open PR heads and `consolidation_plan.md`. I read code only; nothing was built.

## Headline

**G2 removes no capability from the planner as it runs today.** None of the deleted modules can be reached from `run_stage1_to_stage3` / `Stage1ToStage3Pass` on main. Evidence:

- `pass/mod.rs` imported `CostModel`/`DefaultCostModel` only to fill `PlanningModels.cost`. Its own doc says Stage 3 "does not read `cost`".
- `per_computation_candidates.rs` imported only realization helpers from `replacement.rs` (`summary_candidates`, `accuracy_budget`, `default_size_params`, `column_ref`, `summarised_input`). G2 moves these into `realization.rs`.
- Outside `replacement.rs`, the only callers of `EstimatorAccuracy`, `propagate`, `reconciliation`, `allocation`, `rollup`, `grouping`, `rewrite`, `topk_reuse`, `exact_composition`, `explanation`, `erp`, `empirical_*`, `recurrence` and `pane_sharing` are each other, the `dag_export` bin, and the three deleted integration tests.

Everything below marked (c) was **already lost when the planner switched to the stage pipeline**. G2 deletes code that nothing runs. The real question is whether some of that code should be kept or ported for future work. For HLL, the user's observation is correct, and it is already true on main: Pass 1 offers HLL (`summary_candidates`), sized by RSE only (`hll_precision`). `generic_guarantee` gives it `failure_probability: Unknown`, so Stage 3 rejects it for any (ε,δ) target. The only exception is when the deployment's `AccuracyEvidenceProvider::output_guarantee` supplies evidence for that output. `EstimatorAccuracy` was wired only into `ASAPStrategies` (the legacy search).

One consumer outside this repo: sketch-bench `aqpbm-planeval` (`plan.rs:20`, `rows.rs:1005`) uses `asap_aware_mapping::{search_workload, DefaultCostModel}`, pinned to rev `3c31338d`. It keeps building because of the pin. Moving the pin past G2 would mean porting it to `run_stage1_to_stage3`.

## (c) items, by importance

1. **HLL classic confidence** (`ClassicHllConfidence`, `EstimatorContract`): **KEEP the math and tests in G2**, delete only the `EstimatorAccuracy` wrapper and plumbing. **Open an issue** to wire a deployment population contract into Stage 1 HLL sizing and the Stage 3 check (medium). Reason: it is the only (ε,δ) certificate HLL has, it is proof-checked code that is hard to rewrite, and it has no dependency on the legacy code. The user flagged it.
2. **Accuracy composition through operators** (`composition.rs`, `propagate`, `function_rules`, `PropagationStats`, `QuantileInputDomain`, `WorkloadAccuracyEvidence`): **already tracked by #669**. Delete in G2, but add a comment on #669 with the pinned path `e80cfef1:crates/asap-aware-mapping/src/accuracy/{composition.rs,evidence.rs}`, `function_rules.rs` and the `ddsketch_ratio_*` tests, so they can be ported into Stage 1 `composed_guarantee`. Large.
3. **Top-k membership certificate** (`TopKSelection`, `topk_max_distinct_items`): **open an issue** (or add it to #669). Without it, approximate top-k is selectable only through evidence. #589/#593 do not cover membership.
4. **Nested budget allocation** (`allocation.rs`): **open an issue** that depends on #669 (#669 leaves sizing out of scope). Can wait: no example has approximate-over-approximate nesting.
5. **Measured-evidence pricing** (`empirical_cost`, `physical_plan_cost_model` snapshots; `erp` / `empirical_comparison` need no action): **one issue**, "calibrate Stage 3 from sketch-bench `rqe_atomic_costs.json`", after G4's `Stage3Calibration`. Can wait: the §6.3 eval runs in sketch-bench `rqe-optimizer`, not ASAPPlanner. Also note that sketch-bench `aqpbm-planeval` (pinned at `3c31338d`) uses `search_workload`/`DefaultCostModel` and needs a port before it can bump the pin.
6. **Rollup reuse** (`rollup.rs`): **open an issue** (Pass 2 rule). Medium. Not in Examples 1–4.
7. **Composed accumulator collapse** (`composed_aggregate_rewrite`): **open an issue** (Pass 1 or Pass 2 rule). Small. Only a cost optimization; results are already correct.
8. **Top-k limit reuse** (`topk_reuse.rs`): **open an issue** (Pass 2 rule). Small.
9. **Maintained-population (current-series top-k) not offered by Pass 1**: a gap that already exists on main; G2 removes only its adapter. **Open an issue**.
10. Low: sketch-state byte cap (fold into G9 capabilities), posterior-aware sizing (#250 / issue), custom extension families (issue only on demand).
11. Tests: **port 1–2 SQL scenarios** (ClickHouse temporal rate/increase; SQL join binding both children) to the stage pipeline, unless an existing test already covers them. Everything else is covered or moves with #669, G4 and G8.

Nothing needs to be **kept** in G2 except `ClassicHllConfidence`. Everything else is either already replaced, planned (G4/G5/G6/G7/G8/G9/G10/G11, #669), or better tracked as an issue than kept as dead code.
